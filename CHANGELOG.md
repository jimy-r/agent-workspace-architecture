## 2026-08-27

- **The interactive tour caught up to the pattern set, and the reader surface stopped disagreeing with itself.** The tour rendered cards for patterns 1–15 while the set stood at 18; patterns 16 (provenance), 17 (one canonical copy) and 18 (position is price) now render as first-class cards, hand-authored from their PATTERNS.md text. - **Pattern 18: position is price.** The model API is stateless, so an agentic session re-sends its entire transcript on every inference step, and a turn is a chain of steps (every tool call, every file read), not one message. A token's real cost is therefore its size multiplied by the steps remaining after it arrives, which makes an early bulk read the most expensive act in a long session. Prompt caching discounts the repeated prefix, often tenfold, and the re-read still dominates the bill. The pattern manages both multipliers with levers that relocate information rather than surrender it. Bulk reading happens in a subagent whose transcript never enters the caller, and it returns a summary plus a file path because a pasted-back report is re-read for the rest of the session. Ranged reads beat whole files, necessary large reads defer to the step that needs them, independent tool calls batch into one step, standing-surface edits batch to session end so the cached prefix survives, and compaction becomes a deliberate cost tool. The stated cost is that none of it is actionable on intuition alone; build the meter first, because the meter says which read to move. A matching Token-discipline directive ships in [`samples/CLAUDE.md.example`](samples/CLAUDE.md.example). Released as [v1.10.0](https://github.com/jimy-r/agent-workspace-architecture/releases/tag/v1.10.0).

## 2026-08-26

- **A workspace check anyone can run: [`tools/workspace_check.py`](tools/workspace_check.py).** The pattern set gave a reader no way to find out where their own setup actually stands, so the repo answered the interesting question well and the useful one not at all. The tool is one stdlib-only file a stranger downloads and points at their workspace directory. Twelve checks cover the mechanically-checkable subset of the pattern set. They read whether `CLAUDE.md` exists, what the always-loaded surface costs in KB, whether the settings files parse, whether a `PreToolUse` guard has the documented shape, whether a deny floor exists and no blanket allow rule undoes it, credential shapes in text files, `.env` coverage in `.gitignore`, skill and agent frontmatter, `.mcp.json` hygiene, paragraphs duplicated across instruction files, and memory-index size. Each prints one evidence line and the pattern number behind it, and the run ends in a 0 to 10 score with a band. Three things it deliberately does not do. There is no LLM judge anywhere in it, because a judge adds its own variance and the same tree has to score the same twice. There is no network call, no upload, and no execution of anything found in the target tree, which is the only honest posture for a tool that reads other people's private workspaces. And it measures a floor rather than a ceiling. A 10 says the mechanical hygiene is in place and says nothing about whether the roles are any good or the memory points at the right sources, which is the half that still needs a human. Run against this repo it scores 6.4, the honest answer for a documentation mirror rather than a live workspace, and it flags the two audit-canary fixtures as credential shapes, which is the canaries doing their job.

- **Pattern 16: a claim carries its provenance, or it is a guess.** The gap this closes was found by the workspace failing at it twice in one session. A stale session record was reported as live in-flight work, and a completed site deployment was reported as pending, both asserted flat from a record rather than read from current state. Neither was a reasoning failure; both were provenance failures, where an `[unverified]` claim rendered identically to a checked one. The pattern names three mechanisms already running here: cite `path:line` for state claims rather than recalling them, grade load-bearing claims on two axes (source reliability A–E, claim credibility 1–5) plus an `[observed]` / `[inferred]` / `[unverified]` label, and record in a durable brief what would falsify it so a stale document announces its own staleness. The grading scheme was already published in [`samples/roles/researcher.md`](samples/roles/researcher.md) but applied only inside research tasks; the `path:line` rule that extends it to ordinary answers is now lifted into [`samples/CLAUDE.md.example`](samples/CLAUDE.md.example). Scope is deliberately narrow — tagging everything carries the same information as tagging nothing — and the boundary against its neighbours is stated in the page: Pattern 5 governs what memory stores, Pattern 8 measures drift, Pattern 16 governs what a single assertion carries at the moment it is made.

- **Pattern 17: one canonical copy, and pointers from everywhere else.** The companion gap to Pattern 16, and the second of the two problems the workspace names but had never written up. A rule duplicated across the user-global instructions, the workspace instructions and a project file is correct on the day it is written and wrong the first time one copy is edited, with nothing breaking to signal it. The pattern is one canonical location per fact plus explicit pointers, held up by three mechanics: delete the copy rather than summarising it (a summary is a copy that drifts more slowly), banner superseded documents in place so the reader learns which copy governs from the document itself, and scan the always-loaded surface mechanically for boilerplate no single edit introduced. The workspace's own instructions carry the worked instance, left in deliberately: a communication-standards block duplicated into the workspace file had drifted from its source (two bullets diverged, one missing) and was cut back to a pointer. The scanner ships as [`samples/scripts/claudemd_audit.py`](samples/scripts/claudemd_audit.py). Stated cost, because it is real: indirection taxes comprehension, canonical placement has to be decided rather than discovered, and duplication is genuinely cheaper until the first edit.

- **The evaluation method is published: [EVALUATION.md](EVALUATION.md).** The workspace has trended reasoning-regression for months and the concept was a paragraph in the architecture reference; the method itself was never written down usably. It is deliberately unfashionable in three places, and those three are the contribution. **Deterministic checks only, never an LLM judge** — the instrument exists to detect regression over time, and a judge adds its own between-run variance, so a score drop becomes ambiguous about whether the workspace or the judge got worse. **A pass-rate with variance, never a single number** — K=5 replay with a reported standard deviation, because a one-run before/after comparison is noise presented as signal. **Five fixture classes, two of which are the point** — the lucky-correct negative (right answer, wrong process) and the outside-scope case (proves a check does not fire on everything) are the two most often skipped and the two that actually validate the instrument. Every case is frozen from a real recorded failure and carries a `source` field naming it, so the suite is the failure library turned executable, and a case nobody can trace to an incident is a case nobody can defend keeping. Costs are stated rather than elided: authoring is slow, K-replay is five times the tokens, deterministic checks measure a floor and cannot see quality, and cases decay as models stop making the failures they were frozen from. Shipped as samples: the harness ([`samples/scripts/reasoning_golden_run.py`](samples/scripts/reasoning_golden_run.py)), the authoring guide with the full case schema, and three cases covering the transferable check families (`must_cite_path`, `no_fabricated_path`, `uncertainty_tag`). The 89-case corpus is not published — cases encode workspace-specific paths and internal failures, so the method transfers and the corpus does not.

## 2026-08-15

- **Pattern 15: price the lane before you migrate it.** Rising token consumption pushed the workspace to the edge of a structural migration — execution tier to open-weight models, local GPU, a second inference stack. A transcript-walking measurement killed the plan in an afternoon: cost was 88% input-side at a 95% cache-hit rate (a subsidy the migration would forfeit, since open-weight endpoints cache weakly or not at all), the local card could not serve a day's execution volume, and the per-subagent provider routing the design assumed does not exist in the harness. What shipped instead was configuration, cheapest lever first, one variable at a time: always-on workflow orchestration became opt-in, maximum reasoning effort was scoped to judgment lanes (output was ~11% of cost, so effort is a quality dial, not a cost lever), and execution dropped one rung within the provider's own ladder as a registered trial with a kill criterion. The measurement tool itself ships as [`samples/scripts/tier_metrics.py`](samples/scripts/tier_metrics.py) — lane split, cache-hit floor, adoption share, and a rework-marker convention whose denominator is dispatches, not API calls (the first review caught exactly that dilution bug: a per-call ratio made the 20% per-task kill threshold unreachable). The weekly audit consumes its FLAGs as checks-as-code and carries a standing hold/tweak/kill assessment step that sunsets with the trial's review date.

## 2026-08-12

- **The voice web-UI channel was retired — subtraction as the security fix.** A browser-based voice/text web UI (local MCP server serving a LAN page) carried the sharpest open security finding: it bound to all interfaces with no auth, letting any LAN device inject prompts into a zero-prompt agent session. The finding had been "fixed" — a shared-secret gate with a timing-safe compare was added — but the token was opt-in and never configured, so every real launch still ran open. When the task-board walkthrough reached the card, the operator confirmed the channel was unused (an OS-level dictation tool covers voice input now), and the fix became deletion: server folder, launcher script, and every registry row removed in one close-out. Two portable lessons. An opt-in control that ships unconfigured protects nothing — audit the *configured* state, not the code. And for an unused surface, retirement beats hardening: the exposure, its maintenance, and its audit burden all go with it.

## 2026-08-09

- **An external eval library, reviewed the lift-don't-install way.** braintrustdata's autoevals (994★, MIT) and agentbehavior (Apache-2.0) were reviewed by a research fan-out with an adversarial verifier re-checking every load-bearing claim at source. The verdict matched every prior third-party candidate: lift the patterns, install nothing. Two facts decided it, both confirmed in the code rather than the README. The library's unconfigured default routes judge prompts and the caller's API key to the vendor's hosted gateway (the vendor's own test asserts the default), and the companion Claude Code plugin writes raw API keys into settings files and ships every tool input and output off-host unredacted. A licensing sweep also mattered: two of the org's most instructive repos are CC BY-NC-SA or entirely unlicensed, so their principles were kept and their code was not.
- **A reusable choice-scored judge primitive, rebuilt native.** Judge specs are data files (a prompt template plus an explicit choice-to-score map, so partial credit like subset 0.4 / superset 0.6 / equal 1.0 is spec, not code). Verdicts are code-enforced: the returned choice must be in the map, an unparseable or off-map response gets exactly one structured retry with the error appended, and a second failure abstains — it never silently scores zero. Chain-of-thought is forced before the verdict, a criteria mode runs one isolated boolean call per rubric criterion so the judge cannot average away a failure, and every judged variable is auto-wrapped as untrusted content — closing a real injection gap in the upstream library, which interpolates graded text into its judge prompt raw with escaping disabled. House rule carried in the module docstring: deterministic checks first; a judge never gates an unattended lane.
- **The best-of-N judge got the bias controls the review found missing.** The judge now runs a different, higher-tier model than the attempts (measured same-model self-preference runs 10–25%), writes its reasoning before any verdict, picks anchored labels that code maps to numbers, and judges twice — forward and reversed presentation order — with order-sensitivity surfaced to the human instead of resolved silently, plus a computed-aggregate cross-check on the declared winner.
- **Behavior-spec authoring adopted as a skill; the five-class fixture discipline adopted everywhere.** The upstream authoring skill (four markdown files, no scripts, self-contained) was copied with three adaptations and full Apache-2.0 attribution. Its calibration matrix — positive, negative, *lucky-correct negative* (right answer, wrong process), *outside-scope* (proves a check doesn't fire spuriously), allowed boundary — now governs golden-set case authoring and role pressure-testing, and the role template gained the two dimensions it lacked: Evidence (what to inspect before deciding) and Recovery (degrade to a question, never assert from a stale record).
- **A trend-store integrity lesson, the portable kind.** An all-zero record in the reasoning-regression history turned out to be a real run whose 445 calls had all failed on a dead credential — then been hand-flagged by overloading the one field the trend filter happened to read, making the record lie about its own mode. The harness now counts call outcomes per run and self-marks invalid runs in a dedicated field the trend check filters on, and both outage records were re-annotated honestly. An outage must be distinguishable from a regression by the record itself, and an annotation must never overload a field that means something else.

## 2026-08-08

- **The 2-hourly project-manager agent was retired, and delegation became an explicit queue.** Two failure classes killed it. The agent had to infer intent from task lines written for a human reader, so it asked, and its clarifying questions went into a tracker file that was never in anyone's path. Thirteen accumulated unanswered, each freezing the task behind it. Then the unattended runtime rode an ambient credential that expired without a sound, so roughly five weeks of cycles failed dark while the dead-man's-switch alarms landed in channels whose only readers were the dead systems themselves.
- **New module #14, the task board.** One canonical markdown card store for everything outstanding, rendered to a locally served view that regenerates on every request and is never hand-edited. Columns are categories rather than workflow stages, because stage lanes force a second bookkeeping question onto every card and scatter one area's work across three columns. `status` and `area` are fields, so moving a card is a one-line edit. The owner field carries more weight than any other, and a card without a literal next action is not a card. Recurring commitments leave the columns for a collapsed lane excluded from every count, so standing rhythms never inflate the outstanding figure.
- **Delegation is explicit, and the operator's mark is the entire authorization surface.** Only the operator queues a card, and queuing one runs a short intake interview while the intent is still in their head. What does done look like (always confirmed, never inferred), which folders may be written, what constrains the approach, and how should the one or two foreseeable forks be ruled. A drain skill actions the queue on demand inside an ordinary interactive session, checking a template floor on each card first. A fork the intake did not pre-rule is written back onto the card, so the question lives on the thing it is about. No cron sits behind any of it, and the session-start briefing reports the queue count so an undrained queue cannot go quietly stale the way the question tracker did. The first drain closed two of two cards without rework, which is one data point, so the module ships with a review date and a kill condition.
- **Metrics ride the close-out ritual.** A `wrap` step logs a per-task token record as work finishes, and a metrics page charts weekly capacity from that log. Freshness is event-driven by design and the page says so on its face, so a stale tail means no close-out has run rather than a drop in capacity. A scheduled refresh was the obvious build, and it would have reintroduced the fragility that killed the predecessor.
- **Pattern 14, and the samples behind it.** "Delegation is a queue you fill, not work the agent finds" joins PATTERNS.md as the fourteenth entry and the tour as its fourteenth card, and it is the one place in the set where the answer came back negative. New under `samples/board/`: the module design doc, a synthetic card store in the real field format, and the delegation skill carrying its intake interview and drain procedure. The retired design stays in `samples/tasks/` as the studied predecessor, because the classifier and the rejection log still hold wherever the mandate is already unambiguous. README, META_ARCHITECTURE, WORKFLOW, ADOPTION, the samples index, `llms.txt`, and the tour were swept for claims that still read as a live two-hourly cycle.

## 2026-06-21

- **New skill: `goal-design` — a pre-flight for `/goal` loops.** `/goal` runs the agent across turns until a fast model judges a condition met, and that condition is the whole ballgame: it is judged from the conversation transcript only (the evaluator runs nothing itself), so a vague condition loops forever or stops on a false positive. `goal-design` is the pre-flight — it interviews the operator, folds in the target project's real test/lint/build commands, and writes a ready-to-paste `/goal` artifact whose stop-condition is genuinely checkable, with a mandatory turn/time bound. It refuses to emit an artifact when no transcript-surfaceable check exists, routing instead to a one-pass reasoning skill / research flow / normal session — `/goal` is the wrong instrument for judgement work. **Context-durability is the load-bearing addition:** the `/goal`×compaction interaction is undocumented (auto-compaction can summarize away the very evidence the evaluator reads; `/clear` cancels a goal; the bound resets on resume), so every generated goal is built to survive it — re-prove the condition each turn (fresh proof re-enters the transcript), checkpoint progress to a file (recover from disk, not a lossy summary), require a concrete signal a summary cannot fake, and fit one window or decompose. Redacted working copy at `samples/.claude/skills/goal-design/SKILL.md`; new §6 Skills row.

## 2026-06-18

- **Twelfth pattern: "Loop selection — not everything should be a loop."** Hand someone a capable agent and the reflex is to loop every recurring task and remove the human as the bottleneck. Most real work is judgment-heavy, irreversible, or unverifiable, and looping it either deletes the value (the judgment was the point) or ships damage unattended. The pattern is a four-box test: a task earns an autonomous loop only when it is recurring, mechanically verifiable, low-judgment-per-instance, and headless-executable, with an irreversibility override that caps any outward or destructive act (email sent, comment posted, money moved, history pruned) at SURFACE even when all four boxes pass. Three buckets fall out — LOOP, SURFACE, KEEP MANUAL. It is the same route-by-consequence instinct as Pattern 2 (classify-then-act), Pattern 4 (tier-by-impact), Pattern 10 (skill-as-weights gate), and Pattern 11 (scaffold-as-hypothesis): gate by consequence, not by how automatable a thing feels. The card lands as the twelfth tour entry (the JS pattern array goes 11 → 12), and the README tour link and "Start with the why" both move from eleven to twelve.
- **New sample: `samples/scripts/wrap_drift_scan.py`** — the pattern's worked example, redacted to generic placeholders (`<workspace>`). A read-only, print-only close-out surfacer: when a task finishes, it scans the workspace and prints a `## Drift noticed` block — stale CONTEXT.md/PLAN.md by mtime, fired strategy triggers via an optional project-strategy surfacer if one is present, backup staleness, aging open questions — for the operator to action while still in context. It adds no autonomy; the close-out is SURFACE, not LOOP. Exits 0 always so it can never break the host run, every check degrades gracefully, and the only file writes anywhere in it are throwaway fixtures inside a tempdir in the self-test. Listed in the samples inventory.
- **`META_ARCHITECTURE.md` carries the framework.** The loop-stack and four-box selection test go into the Session-workflow module (which owns `wrap`) and the generalized drift-scan is named alongside it; the header note records the sync. The credit goes to LangChain (*The Art of Loop Engineering*, the loop STACK) and latent.space / Swyx (*Loopcraft*, stack-loops + move-up-for-leverage / down-for-reliability), added to `ATTRIBUTION.md`. The workspace's own contribution is the selection discipline (which work earns a loop), the restraint the sources' "remove the bottleneck" energy under-emphasises for a solo operator whose judgment is the product.

## 2026-06-16

- **New module: Sentinel — zero-prompt pass-through with a silent deny-floor and a quiet monitor.** The source workspace was suffering approval fatigue, so it removed *all* interactive permission prompts — the reframe being that prompts are separable from enforcement: the deterministic hooks already allow/block in code without asking. The posture is now `permissions.defaultMode = bypassPermissions` (no prompts) over a hardened, always-applies `permissions.deny` floor that silently blocks the irreversible / outward / self-modifying minority — catastrophic recursive deletes (re-homed from `autoMode.hard_deny`, which doesn't apply under bypass), force-push / push-to-main, and edits to the security envelope itself (settings, MCP config, the hook scripts, the scheduled-tasks dir). On top sits a deterministic PostToolUse **action-log + hard-tripwire desktop toast**: it records every tool call (shapes/hashes, never secrets) and notifies only on a closed set of genuinely dangerous post-hoc signals (an executed envelope write, an exec-hijack / force-push that ran, raw shell egress, a credential-shaped string in an outbound payload, a read of a known secret-key file). Near-zero false alerts by construction — silent-log default, closed toast set, time-windowed dedup, reads never toasted. The semantic LLM-judge digest (the "something truly unusual" layer) is deliberately **deferred** until the action-log has real data to tune its bar against; shipping it untuned would just trade approval fatigue for alert fatigue. Honest residual carried in §2 / §11: the reversible majority shifts from prevention to detection, and an in-process script write or egress bypasses the shell + edit layers (detection-only, backstopped by the encrypted backup). New §2 module row, §5 hook row, §11 floor description; the Security-envelope row's `autoMode.hard_deny` reference re-homed to the `permissions.deny` floor.
