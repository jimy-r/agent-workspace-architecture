## Protocol

- **Question.** Which tool results are the biggest entries into main-thread context, and how much of each is ever used again, or read again soon after?
- **Data.** Main transcripts (`*.jsonl` in the Claude Code project folder for `<workspace>`, resolved in code from `session_report.PROJECT_DIR`) whose first request falls on a local date from 2026-08-29 to 2026-09-28, as they stand at run time. Classes as in E1: interactive (first entrypoint `claude-desktop`) and headless (any other). Subagent transcripts (`*/subagents/agent-*.jsonl` and `*/subagents/workflows/*/agent-*.jsonl`) under the same date rule go in separate tables and do not enter H1. Lines marked `isSidechain` are skipped. A file is a session.
- **Requests.** One request per assistant message id with usage and a context above zero. Context is `input_tokens` + `cache_read_input_tokens` + `cache_creation_input_tokens`, per-field max across the id's lines, as `cache_write_scan.load_steps` does. Zero-context (`<synthetic>`) messages are not requests, and their text is not assistant output.
- **Unit.** One `tool_result` block in a user message, tied to its `tool_use` by id. It enters context at the first request after it (the next request). The request before it closes the prior turn. Tool label: the `tool_use` name, with MCP tools grouped as `mcp:<server>` and results with no matching `tool_use` as `unknown`.
- **Tokens.** A result's tokens are the next request's input growth: the next request's context, minus the previous request's context, minus the previous request's `output_tokens`, floored at zero and shared across all results in that gap in proportion to their characters (equally when all are empty). Characters are the result's text characters; each image or document block counts as 6,400 characters (about the 1,600 tokens of a full-size image, at 4 characters per token), and any other block counts its JSON length. One method throughout, main and subagent.
- **Unmeasured results.** Left out of token and dollar totals and counted by reason: no request after the result (the session ended or was interrupted), a compaction marker (`isCompactSummary` or `type` `summary`, as `cache_write_scan` detects it) in the gap, a model change between the two requests, or no request before the result. Gaps whose growth is zero or less are measured at zero tokens and counted.
- **Dollars.** API-equivalent carry cost. Rates come from `scripts/tier_metrics.py` (`price_per_million`, `CACHE_READ_MULTIPLIER`, `CACHE_WRITE_MULTIPLIER`) and the re-write threshold from `scripts/cache_write_scan.py` (`REWRITE_SHARE`), imported and never retyped. A result's tokens are written once at the next request, at the input rate times the lane's write multiplier (main 2x, subagent 1.25x). They are then billed on every later request of the same file until a compaction marker or the end of the file, at that request's cache-read rate, or at the lane's write rate when that request is a re-write (cache write above `REWRITE_SHARE` of its context). Each request is priced at its own model's rates.
- **Referenced.** A result is referenced when a later assistant text block or `tool_use` input in the same file contains a distinctive span of the result. Later means a request after the result entered context. Blocks of the request that issued the call never count, even when logged after the result. `tool_use` inputs contribute their values, never their keys. Thinking blocks are not assistant text. Read results have their `cat -n` line-number prefixes stripped before spans are taken. Spans:
  - *File path.* A run of non-space characters with `/` or `\` between two name characters, trimmed of surrounding quotes, brackets and punctuation, at least 6 characters long. It is normalised to lower case, `\` to `/`, repeated `/` collapsed, a git-bash drive prefix `/x/` to `x:/`, and a trailing `:<line>` suffix or `/` dropped. When the path has three or more components, its last two also count as a span if they reach 10 characters.
  - *Identifier.* A run of letters, digits and `_`, optionally joined by `.` or `-`, at least 5 characters long, holding a letter or `_`, and holding at least one of: a `_`, a lower-to-upper case hump, both a letter and a digit, a `.` between two parts, or two or more `-`.
  - *Number.* A run of 4 or more digits that touches no letter or digit, after thousands commas are dropped.
  - *8-word shingle.* 8 consecutive words, where words are the lower-cased runs of `[a-z0-9_]`.
  - *Distinctive.* A span counts only if it did not occur in the file's context up to and including the request that issued the call, counting from the last compaction marker: user messages, earlier results, a compaction summary, and assistant text and `tool_use` inputs. Content that arrives in the same gap as the result (other results, a user message) does not count against it.
- **Never referenced.** A measured result with no referenced span. The share is taken over tokens, with the dollar share beside it.
- **Re-read.** A result is re-read when one of the 5 requests after it entered context issues a call with the same key: Read by normalised `file_path`, Bash and PowerShell by the command with whitespace collapsed, Grep and Glob by their full input, WebFetch by URL. Other tools have no key and show n/a. The rate is re-read results over keyed results.
- **Size bands.** By measured tokens: under 500, 500 to 1,999, 2,000 to 7,999, 8,000 to 31,999, and 32,000 and over.
- **Tables.** By tool and by size band, for the main thread and, separately, for subagents: results, tokens, dollars, never-referenced share of tokens and of dollars, and re-read rate. Tools under 0.5% of a table's tokens sum into one row.
- **Matcher validation.** Runs before the full run. Frame: measured main-thread results in the window with more than zero tokens and at most 30 requests from the one they entered at to the end of their file, so the whole later context can be shown. Order: weighted by tokens, with keys `u ** (1 / tokens)` drawn from `random.Random(20260928)` over the frame in file-then-line order, highest key first. The script writes each sample to `tasks/experiments/E2/validation/` with likely secrets redacted and no matcher output: the call (tool and input), the issuing request's text, the result (its first 3,000 and last 1,000 characters when longer), and every later request's text and `tool_use` inputs, each value capped at 2,000 characters. Samples are labelled in order until 20 are referenced and 20 unreferenced, and the first 20 of each form the set. A sample that cannot be judged is marked skip. Label rule: referenced when a later assistant text or tool input carries specific content that this result supplied and the context did not already hold (a path, name, number, passage or code, quoted or paraphrased). Using only the gist (success, failure, empty, updated) is unreferenced. Labels, each with a one-line evidence note, are saved before the matcher runs on the set. Pass: the matcher marks at least 18 of the 20 referenced and at most 2 of the 20 unreferenced as referenced.
- **One revision.** The span definition may be tightened once, at one of two points. The first is after labelling and before the matcher runs on the set. The second is after a failed validation, in which case the revised matcher is validated on a fresh set (the next 20 and 20 in the same order, labelled before it runs). The revision is appended to this Protocol, and its hash is saved as a second line of `tasks/experiments/E2/protocol.sha256` before the matcher runs again. There is no second revision.
- **Hash.** sha256 of this file from the `## Protocol` line up to, but not including, the `## Result` line, as UTF-8 with `\n` line endings, computed by `scripts/experiments/e2_tool_output.py --protocol-hash`.

## Hypotheses

- **H1, never referenced.** 25% or more of main-thread tool-result tokens (interactive and headless together, measured results only) are never referenced later in their session.
- The replay hypothesis (the fixed hook cuts per-task cost 10% or more, turns up no more than 5%, quality non-inferior) is not tested in this pass. It waits for the `compress-hook-tool-shaped` patch.

## Decision rules

- If H1 passes, that is evidence a result-trimming hook has room to save. The replay targets the tools and size bands holding the most never-referenced tokens, once the user applies the patch.
- If H1 fails, the program's 25% premise does not hold. The replay's saving is capped near the measured share, and the main thread takes that to the user before the replay is scheduled.
- If H1 is INCONCLUSIVE (validation fails after at most one revision, or there are no measured results), the tables stand as sizing only and no reference-based figure is used.
- Re-read rates carry no verdict. A tool or band re-read at 20% or more is listed as a watch item for the replay, where a trimmed result may be fetched again.
- No verdict changes a hook, rule or setting tonight.

**Quality guard.** None needed. The analysis is offline and changes no behaviour.

**Budget.** No model spend beyond this build agent.
