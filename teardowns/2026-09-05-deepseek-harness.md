# Teardown: DeepSeek Harness

- **Revision read:** `d347e703908d` (master, 2026-09-04); surfaces read: `README.md`, `AGENTS.md`, `SAFETY.md`, `CONTRIBUTING.md`, `docs/architecture.md`, `docs/AGENTS.md`, `docs/testing.md`, `docs/tool-execution-pipeline.md`, the `docs/subsystems/` pages for session, compaction, sandbox, approval, credentials and token-meter, the `.agents/notes/` README plus six Agent Notes, the `hooks`, `guard` and `agent-instructions` package READMEs, and the public exchange in [discussion #1345](https://github.com/deepseek-ai/deepseek-harness/discussions/1345). ## What it is

DeepSeek Harness (`dsh`) is DeepSeek's agent runtime, built on Cordis, a framework for dependency injection, and the repository description is meant literally. "Every part of the product is a plugin, including the model adapter, the tool registry, the session log, and the agent loop itself" (`docs/architecture.md`). It shipped as a developer preview on 2026-08-13, promises breaking changes in capital letters in the README, and had 212k stars three weeks later. `SAFETY.md` says plainly that it "has not undergone a security audit and must not be treated as secure or production-ready."

## What works

**One home per fact, held up three ways (pattern 17).** The documentation tier table states the rule outright, "Each fact has one home: the tier whose job it is; elsewhere, link there" (`docs/AGENTS.md`), and then the project stops trusting the rule and builds it into the filesystem. `CLAUDE.md` is a symlink to `AGENTS.md` at four levels of the tree, with the instruction "edit the real file" (`AGENTS.md`). The context loader dedups at runtime too, so "a `CLAUDE.md` that duplicates its `AGENTS.md` is not repeated" (`packages/context/agent-instructions/README.md`). I have argued for the pointer discipline in a lot of places. This is the first published repo I have seen that removes the drift class by construction instead of policing it.

**A guard has to be shown to fail (pattern 11).** "A guard only guards if the regression fails it," with the procedure written out as "introduce the regression, watch red, revert" (`docs/testing.md`). The same page carries "Verify the world, not the self-report," on the grounds that "a keyword probe on the agent's own output lets a cheating agent pass." Fifty-three `verify-*` scripts sit behind that stance, covering the format of decision records, link and anchor integrity, word budgets on the instruction files loaded at start, pasted type declarations and archive hashes. Coverage is gated at per-file 100% and the doc says in the same breath that coverage proves nothing about behaviour. That is a rare pairing.

**Position is priced, with a worked example (pattern 18).** The Agent Note behind the 2026-07-21 compaction fix moves the summarisation instruction "from the **front** of the request" to the end of the conversation so the cached prefix survives, and keeps unused tool schemas in the payload because "dropping them would shorten the token sequence and break alignment with the cached request." Most write-ups of prompt caching stop at "keep the prefix stable." This one shows the two concrete edits that follow from taking the rule seriously, and it sits next to a 65,536-byte budget for workspace instruction files with a stated eviction order, "broader files are omitted before the most specific file is truncated" (pattern 9).

**Decision records with the losing options attached (pattern 16).** "Every non-trivial change MUST add or update at least one Agent Note in the same PR," each note carries an alternatives section, and "Alternatives are recorded, never invented" (`.agents/notes/README.md`). There are roughly 870 of them at this revision, partitioned by lifecycle folder, with archived notes frozen under a hash manifest. A record of what a change beat is worth more than a record of what it did, and this project makes the former mandatory.

The permission story is solid as well. Approval fails closed, so "a missing, non-owning, throwing, or non-conforming answerer becomes `unavailable` rather than opening the gate" (`docs/subsystems/approval.md`), credentials travel as references to environment variables rather than as values (`docs/subsystems/credentials.md`), and existing Claude Code and Codex hook files run unmodified inside the tool pipeline (`packages/hooks/README.md`). Patterns 4, 6 and 7, all present.

## The trade-offs

**No privileged core also means no owner for the awkward capabilities.** "There is no privileged core to patch" (`docs/architecture.md`) buys swappability at every seam. It pays where a capability is asked for by users and owned by nobody. The memory decision below is the clearest case. The project's own note says "There is no memory preset registry, vendor-specific DSH plugin, universal memory service, installation UI, migration layer, health checker, or reconnect controller" (`.agents/notes/implemented/feature/2026-07-31-third-party-memory-mcp-examples.md`), and the user guide adds that the three example configurations that do exist are default-off and that their inclusion "does not imply endorsement" (`docs/user/guide/mcp-memory.md`). The feature users ask for most lives in plugins the project does not curate.

**Heavy gating and human merging keep the tree coherent, and still miss the drift the gates can't see.** The project accepts no outside code, "We are sorry that we cannot accept external pull requests at the moment" (`CONTRIBUTING.md`), and every change carries a record. That discipline is why the repo reads as one design. But at this revision the repository-layout block in `AGENTS.md`, the file every agent session loads first, lists a `self-modification/` package group and a `support/` group, and neither exists anywhere in the tree's 10,554 entries. Fifty-three verifiers and a word budget on that exact file, and the description of the tree that every session loads is wrong about the tree. A budget guard checks length.

**Preview velocity.** A tag every one to three days through late August and early September. Meanwhile the proposal that would give the model recall after compaction, `recallable-compaction`, has sat at `Status: proposed` since 2026-07-06. Shipping fast and thinking slowly about state is a choice, and it shows up as the absences below.

## What's conspicuously absent

**Memory that outlives a session (pattern 5).** Everything durable here derives from the session log. "Fork, resume, transcripts, telemetry, and persistence all derive from these durable settlements" (`docs/architecture.md`). Fork copies a prefix and resume reopens the same log, and both stay inside one session's lineage. Nothing carries a fact from session A into an unrelated session B. Read strictly, the only carrier across sessions the harness ships is the instruction file the user writes by hand, capped at 64 KB. The team knows this. Their own proposal opens with "Compaction is irreversible from the model's current context" and claims that "No mainstream coding harness gives the model in-loop recall" (`.agents/notes/proposed/feature/2026-07-06-recallable-compaction.md`). Discussion #1345 asked for persistent memory on 2026-08-14 and drew four community plugins within days. I posted the write discipline we run (memory points at the source rather than copying it, every write is add, update, delete or no-op, verify before asserting, an index ceiling with a migration rule) into that thread, and the author of one of those plugins, `dsh-memory-gate`, said the rules were "exactly the spec we needed" and would go into their next iteration. That is a plugin author's roadmap, not a project commitment. The harness itself still ships no memory, and by the note above, it has decided not to.

**A second lens on its own judgement (pattern 13).** The scepticism in this repo is aimed entirely at code. Guards need negative controls, self-reports are not evidence, invented checks are a review blocker. None of it is aimed at the review itself. `dsh-code-review` is a checklist read in the same frame as the code. No slice is held out. Nothing measures whether a review changed a call. A project this careful about dead checks has no way to detect a dead reviewer.

**The improvement half of the audit (pattern 8).** The housekeeping half is heavily mechanised. What is missing is the scheduled pass that reads outside sources and critiques the repo against them, with a finding ledger and the rate at which findings are accepted or dismissed. The `architectural-conformance` proposal from June wants some of this and is still proposed.

**A delegation channel (pattern 14).** Work reaches the team through Discussions and an internal board. There is no queue anyone outside can fill with a done-when and a write scope, which follows directly from the stance on external pull requests.

## What this teaches

A harness can be fastidious about code and have no theory of state across sessions. "Everything is a plugin" is a real architecture, and at the boundary it is also "everything is somebody else's problem." The memory decision is coherent on its own terms, since a seam that any MCP server can fill is cheaper than owning one more vendor adaptation, but it leaves persistence to whoever writes the instruction file and whichever plugin the user happened to install. If your workspace runs on a harness that has declined to own memory, the write discipline is now yours. A budget with an eviction order is then your whole persistence policy, and it is worth writing that down as a policy rather than discovering it as a limit.

Two lifts transfer straight across. Symlink the duplicate instruction file instead of maintaining two copies, and prove every guard fails before you trust it green. Both cost an afternoon. The harder one to lift is the honesty of the Agent Note format, where a change has to name what it beat and cannot invent the alternatives. I would take that over another verifier.
