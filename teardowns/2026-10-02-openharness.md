## What it is

OpenHarness is a command centre for coding agents, published by the `autonomous-ai` organisation. One daemon per machine runs Claude Code, Codex and a dozen other agent CLIs in tmux panes, and the README states the stance plainly. "Harness never wraps an agent. It reads transcripts and uses the vendor's own hooks." The repository also holds a Store of fifty domain packages and, less advertised, the working record of the agents that build the product, kept as dated handoffs, review rounds, plans and audits under `docs/research/`, `docs/plans/` and `work/`. That record is what this page reads. A different project, `HKUDS/OpenHarness`, shares the name and nothing else.

## What works

**A claim is bounded by what ran (pattern [16](../PATTERNS.md#16-a-claim-carries-its-provenance-or-it-is-a-guess)).** The root `AGENTS.md` is twenty lines, and most of them are about evidence. "Reuse evidence only for the source and environment it covers." "Never describe an incomplete or failed suite as passing." Behind the rule sits `scripts/validate-change.py`. It runs an explicit plan of checks and writes a receipt holding the commit, the tree and a SHA-256 over the uncommitted diff plus every untracked file, because, as its comment says, "A SHA alone would falsely identify a dirty checkout as tested HEAD." If that fingerprint moves while the checks run, the whole receipt is marked `source_changed`. A memory-quality run that completed zero of six cases is committed with `"rate": null` and the line "Empty, unfinished or partially reviewed denominators never receive a passing rate" (`docs/research/2026-10-01-memory-quality-review-blocked.json`). I would have been tempted to delete that file.

**Handoffs that say what is not proven.** `HANDOFF.md` has a section titled "What remains unproven", and it is blunt. "Passing software checks does not establish the user's subjective “wow” bar." It tells the next agent what it may not claim, as in "Do not describe this as a diagnosed/fixed resolver bug." The phone handoff separates "Decisions already made by the user (do not re-propose)" from "Proposals that need the user's decision (do not build without it)" (`docs/research/2026-09-28-phone-overnight.md`). A superseded handoff keeps its body under a dated banner that says which parts no longer hold (`docs/research/2026-09-27-hn-handoff.md`). I hand work between sessions every day, and my own schema had none of those four sections.

**Guards that are shown to fail (pattern [11](../PATTERNS.md#11-a-scaffold-is-a-hypothesis--gate-it-behind-a-measurable-signal)).** The provider conformance suite "is itself tested against deliberate breaks", with "Eleven broken providers, each violating exactly one rule, each of which the runner must catch" (`provider/reference-provider/README.md`). The review rounds apply the same idea to builds. Each round freezes a binary by SHA-256, and the round 19 fix ships with a regression that "passes on the corrected candidate and fails at the replacement-question check on frozen `32f43bb0`". The round 20 reviewer then says of the repository's own run of that regression that "its separate root run is not counted as independent execution in this score."

**A self-edit loop with a person in it (pattern [10](../PATTERNS.md#10-a-skill-is-editable-weights--never-adopt-a-self-edit-without-a-gate)).** `daemons/LEARNING.md` describes a loop that turns agent mistakes into shared lessons, and nearly every line narrows it. It notices three signals only, "a correction, the same failure twice, the same steps three times". The distilling prompt says three times that the expected answer is no lesson. Anything an agent or a tool wrote is treated as untrusted and is redacted before it reaches a prompt. The proposal step promises that "nothing is taught without your yes", each approved lesson is one commit that can be reverted, and an unused lesson is archived at 90 days. The doc names its own limit as well. "Approval is guarded against agents, not against same-user malware."

The smaller pieces hold the same line. A Store package is a manifest, instructions, a pinned toolchain and a check, and the host "reads one manifest, copies files into the workspace, runs the commands the manifest declares, and watches one JSON file" (`store/README.md`, pattern [1](../PATTERNS.md#1-pure-roles-composed-with-project-facts)). The action gate classifies tool calls before the engine runs them, to "ask before risky writes, refuse the unrecoverable" (`cli/src/lib/actionPolicy.ts`, patterns [4](../PATTERNS.md#4-tier-by-mechanical-impact-not-by-tone) and [7](../PATTERNS.md#7-a-cheap-hook-beats-a-careful-agent)).

## The trade-offs

**The receipt replaced the pull-request check.** CI ran on every pull request for six days in September and was then switched off, because on a shared runner "a red check on a PR said more about the runner than about the change" (`.github/workflows/ci.yml`). It now runs by hand, and `CONTRIBUTING.md` says plainly that "a PR does not automatically exercise the app, real engines, or hardware." So the verdict on a branch is the receipt the authoring agent produced, plus whatever a reviewer chose to run. The provenance is excellent and the enforcement is voluntary (pattern [3](../PATTERNS.md#3-make-silent-failure-loud-the-dead-mans-switch), partial). The evidence has a shelf life too. Fifty-one Markdown files under `docs/`, `work/` and the root handoff point at `/tmp` paths for their logs and drivers. A reader on another machine can check the shape of a claim and can't open what it rests on.

**Speed got measured after it hurt.** The team audited 48 hours of its own agent-run releases, 56 of them, and found repeated full suites, the same 23 baseline failures rediscovered and a full disk in the middle of a release (`docs/performance/2026-10-02-release-process-audit.md`). One 29-minute gap "must not be attributed to GitHub or claimed fixed by a repository patch." It ends on a commitment. "Measure the next ten tasks end to end before claiming the target is achieved." That is instrument first and change second, with time as the unit (pattern [15](../PATTERNS.md#15-price-the-lane-before-you-migrate-it), partial).

**A synthetic panel stood in for the user, once.** An overnight run on the phone app used "a panel of AI users playing the target audience, whose feedback drives the fine-tuning", and the panel's scores rose from 6 to 8 or better over four rounds. One panel-driven change shipped in a build and the user had it reversed. The follow-up audit records the correction in two sentences I'd pin above any persona review. "Panel preferences do not supersede the user's specified interaction design", and the scores "are not user approval of the design choices above" (`docs/research/2026-09-28-mobile-ui-change-audit.md`). The frozen-build rounds are a real second lens. The panel was a second lens whose score became the stop condition (pattern [13](../PATTERNS.md#13-challenge-half-formed-ideas-with-a-different-lens--and-hold-a-sample-back-to-prove-it-helps), partial).

## What's conspicuously absent

**A budget on its own instruction files (pattern [9](../PATTERNS.md#9-context-is-a-budget-not-a-constant)).** The team budgets disk before a test run, a deadline per check, and six memory-inference calls an hour (`cli/src/memory/budget.ts`). The tokens every session pays first get no budget. Root `AGENTS.md` is twenty lines that point at two docs. `desktop/CLAUDE.md` is 670 lines and 55,926 bytes, which Claude Code loads for any session working in that folder, and it carries change history beside invariants, down to a paragraph about a feature removed on 2026-09-11.

**A standing audit (pattern [8](../PATTERNS.md#8-audit-the-workspace-like-a-fitness-function)).** The audits I found in this tree were written after something hurt, the release audit above and the rebuild audit in `work/REVIEW.md`. None of the fifteen workflows runs on a schedule. Nothing asks the question again next month, so the "next ten tasks" promise rests on someone remembering it.

**A home for rules no check enforces (pattern [17](../PATTERNS.md#17-one-canonical-copy-and-pointers-from-everywhere-else), partial).** A filename search of the whole tree finds no lessons or post-mortem file for the team's own process. An incident lives beside the check that came out of it, like the lockfile step in `ci.yml` whose comment recounts the afternoon it cost. I think that is the right default. It leaves a rule with no check behind it nowhere to live except a doc that other docs can contradict. `docs/terminology.md` says to use Tab for a workspace group "in all visible copy", while the README and `docs/keyboard.md` still say Swarm.

Memory across sessions (pattern [5](../PATTERNS.md#5-memory-points-it-doesnt-mirror)) is partial for a different reason. A memory is admitted only when its evidence quote is a literal substring of the source (`cli/src/memory/admission.ts`), and a reference is stored as "where to verify, not a permanent copy". It is also experimental and off by default, and the design doc reports "zero completed extractions, no quality score" from its real-model runs so far (`docs/plans/2026-09-30-tim-memory.md`).

## What this teaches

When agents build, review and release, the scarce thing is a claim you can trust without re-running it. This repo's answer is to make each claim carry its own scope: which tree, which checks, what was not run, who authorised what, and what the next agent must not say. All of that transfers to a one-person workspace, and none of it needs the product.

The limit shows in the same files. A receipt written by the agent that did the work is still a self-report until something the agent doesn't control reads it. The round 20 reviewer understood that when it refused to count the repository's own regression run. The pull-request path has no such reviewer yet.

**What changed here:** The handoff schema in my own workspace gained four sections on 2026-10-02, the day of this reading. A handoff between sessions now lists the claims the next session must not make, what is authorised and what is still gated, pointers to the rulings in force, and a superseded-by banner. The skill that carries it is not among this repo's samples yet, so the record is this repo's [CHANGELOG](../CHANGELOG.md) entry for 2026-10-02. One idea was rejected. A persona panel's score will not gate anything here, because a score an agent can raise by iterating is advice, and the user stays the arbiter. Three more lifts are deferred to a wider review of the same repository: the fingerprinted receipt, suite hashes with a null rate, and the frozen-build round rules.
