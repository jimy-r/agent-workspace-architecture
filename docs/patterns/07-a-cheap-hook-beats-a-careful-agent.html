Pattern 7

A cheap hook beats a careful agent

Problem. An agent that has misread the task can overwrite your .env, delete a record, or force-push. "Be more careful" does not scale.

Pattern. A PreToolUse hook intercepts file writes and shell commands against a blocklist (sensitive paths, destructive verbs, pushes to protected branches, exec-hijacking env-var prefixes like GIT_SSH_COMMAND='…' git fetch) and blocks them before they run. It fails closed on the failures its own code cannot catch. The hook entry sets "onFailure": "block" (Claude Code 2.1.295 or later), so a guard that cannot start, crashes before it answers or is killed at its timeout refuses the call. The entry names its interpreter by full path, so a PATH change can neither break the guard nor swap in another Python. An error the guard catches in its own code still lets the call through and writes an error row that an audit check counts, so one bad pattern cannot refuse every shell command.

Why this beats the obvious. Trusting the model to never err is a hope, not a control. A ten-line deterministic check catches the large majority of accidental damage for almost nothing. Until 2026-10-12 the guard failed open everywhere, on the view that a broken guard must never wedge the session. The trade flipped once the failure modes were listed. In Claude Code only exit code 2 blocks by default, so a guard whose interpreter has gone missing lets every call through and says nothing, and one PATH change does that to every guard at once. A wedged session shows on the next tool call. A guard that quietly stopped running shows only after the damage it should have stopped has landed. A probe on the desktop and terminal builds found a guard that could not start letting the call through without the setting and refusing it with the setting.

Cost. Occasional false positives (a legitimately named file that matches a protected substring), best resolved by naming around them rather than widening the gap. Failing closed adds a second cost. A guard that cannot start refuses every call it gates, so a missing interpreter wedges the session until someone repairs it. The full-path interpreter removes the cause that hits every guard at once, because a PATH edit, a new virtual environment or a second Python earlier on the path no longer changes what runs. Moving or uninstalling that interpreter still wedges the session, so keep a recovery script that takes the setting off without needing Python, and a check that warns when the pinned interpreter is missing.

Where it lives: samples/scripts/security/check_bash_command.py and the hook config in samples/.claude/settings.example.json.
